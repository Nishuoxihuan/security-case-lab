## 为什么这个攻击面在近五年变得重要

API 早已是业务的主入口：移动端、小程序、开放平台，背后都是 API。
而 AI Agent 的出现带来了新变量——模型可以调用工具、读取文档、执行操作，
传统的「用户—权限」模型里，突然多了一个「模型—工具」的新信任边界。

## 常见的失效模式

- **对象级授权缺失（BOLA/IDOR）**：改个 ID 就看到别人的数据，API 漏洞的常年榜首。
- **属性级过度暴露**：返回了前端用不到的敏感字段。
- **提示注入**：恶意输入改写模型指令，间接操纵工具调用。
- **高权限工具无确认**：Agent 能删库，却没有人类确认环节。

## 防守方抓手

服务端强制授权（不信任客户端传来的身份断言）、字段级权限、Schema 审核、
工具 allowlist、敏感操作人工确认、全链路操作日志。读案例时注意区分：
这是「协议实现错了」，还是「信任模型一开始就假设错了」——后者更值得研究。
